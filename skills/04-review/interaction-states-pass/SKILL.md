# 交互状态完整性检查

## 1. 盘点行为

列出目标范围内的交互元素及其真实动作：导航、提交、选择、筛选、展开、关闭等。按行为决定所需状态，静态卡片不增加 hover，普通同步链接不增加 loading。

## 2. 检查适用状态

- **默认**：操作用途可识别，链接与正文可区分，触摸和键盘用户不依赖 hover 才发现动作。
- **Hover / active**：有合适反馈且不影响布局或制造禁用歧义；不强制阴影、位移、缩放或特定透明度。
- **Focus**：键盘焦点可见且不被内容遮挡；已有浏览器或组件焦点样式有效时保留。不能移除 outline 又不给替代。
- **Disabled**：确有业务禁用条件时，语义与实际行为一致。原因通过可访问的文字说明，不仅放在禁用控件的 title 或 hover tooltip 中。
- **Loading**：真实或明确模拟的异步操作提供反馈、防重复触发和恢复路径。保留操作名称；必要时用状态播报说明进度与结果。
- **选中 / 展开 / 当前**：视觉状态与 `aria-selected`、`aria-expanded`、`aria-current` 等适用语义一致。

## 3. 验证完整流程

检查成功、失败、错误修正、返回和重复操作。表单错误关联具体字段；失败后可重试且不丢失必要输入。模态框管理进入、内部移动、关闭和焦点返回；组合控件按其模式支持方向键，不要求内部每项都进入 Tab 顺序。

动效用于解释状态，可即时变化，不把 0ms 判为缺陷。使用动效时沿用系统时长，尊重 reduced-motion，不延迟焦点出现。

## 4. 输出或修复

列出元素、适用状态、通过/失败/未验证及证据，不把不适用状态计为缺失。视觉截图不能证明键盘或异步行为通过。

默认报告；用户要求修复时，在原设计系统中补齐问题并复验。无障碍数值和判定依据见 [standards.md](../../../references/standards.md) §15。

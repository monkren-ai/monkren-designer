# 无障碍审查

## 1. 范围与依据

读取用户指定页面、相关组件、样式和状态实现。默认目标为 WCAG 2.2 AA，沿用项目明确指定的版本与级别。先读 [共享标准](../../../references/standards.md) §15；具体判定涉及边界或例外时查相应 W3C 原文。

默认当前 agent 完成四个检查面，不依赖子 agent、浏览器或特定测试库。无渲染能力时做静态检查，未测行为标为未验证，不用推断冒充测试。

## 2. 四个检查面

### 对比度与色彩

解析实际前景、背景、透明度、字号和字重，再按 §15 阈值计算。图片和渐变背景需检查文字覆盖位置，无法确定时记录待验证。

检查颜色是否为状态的唯一信号。纯黑白不是无障碍缺陷；品牌色、禁用态、Logo 与装饰的适用条款和例外分别核对。报告实测值与要求值，不向上四舍五入使其通过。

### 语义与内容

检查名称、角色、值、标题层级、landmark、图片替代文本和字段标签。优先原生 button、link、input；自定义控件按实际语义和键盘行为判断，不因使用 div 就自动判失败。

可见字段提示不能只靠 placeholder。图标按钮须有可访问名称，但有效名称不只来自 `aria-label`。不把“恰好一个 h1”等结构偏好直接称为 WCAG 强制条款。

### 键盘与焦点

走完整关键操作：Tab 顺序、控件内部方向键、激活、退出和恢复焦点。验证可见焦点、焦点遮挡、键盘陷阱与重复导航的跳过方式。

模态框检查初始焦点、内部移动、关闭与回到触发器；菜单、select、disclosure 按各自模式判断，不把所有 dropdown 当成相同控件。

### 动效、表单与目标区域

检查自动播放的控制、闪烁风险、减少非必要动效、错误关联、必填提示、输入目的与状态播报。不要把暂停按钮视为危险闪烁的充分修复。

目标区域根据 AA 最小尺寸和间距等例外判断，更宽裕的触摸建议单列。检查缩放、重排和移动布局，确保错误与控件不因窄屏不可用。

## 3. 报告与修复

去重后按共享 P0–P3 排序，每条给位置、影响、证据、适用条款、建议及验收条件。区分已确认失败、待验证风险、最佳实践建议与第三方限制。

默认报告；用户已要求修复时实施并复验对应条款和关键路径，不重新索要已有授权。交付说明测试方法、页面/状态覆盖和未验证范围，不以构建通过或自动扫描通过宣称整站合规。

# 产出与交付约定

只在需要选择交付格式、保存位置或编写独立演示时读取。用户指定格式、路径和数量优先；根技能决定权限，具体模块决定任务流程。

## 1. 格式选择

研究、建议和审查默认在对话中交付，不自动创建目录或修改项目。用户要求保存、导出或制作文档时，写相应报告；只生成用户需要的格式，不默认同时生成 Markdown、HTML 和评分提升报告。

简单请求用简短结论与证据；复杂报告按问题规模展开，不强迫所有任务使用同一模板。

## 2. 审查报告

推荐顺序：

1. 按 P0–P3 排序的发现，每条有位置、影响、证据、建议、验收条件。
2. 五维评分及证据（任务需要且足以评分时）。
3. 已有设计值得保留之处。
4. 覆盖的页面、视口、状态，未验证项与限制。
5. 简短结论和优先行动。

“没有发现已确认问题”是有效结果，不为填模板编问题。全部未验证时不能宣称通过。

## 3. 设计方向建议

说明当前目标、约束和设计起点。按用户指定数量；未指定且确需比较时默认三个方向。每个方向可包含：视觉原则、布局骨架、关键 token、适配原因、参考与证据、代价、下一步验证。

对比方案不必来自互斥流派，结构方案也不必变化品牌字体。提到真实产品案例时验证来源；没有外部证据时说明是设计推断，不用假案例填字段。

给出推荐并说明取舍。用户只选了方向时记录选择；是否继续制作取决于已有任务授权，不自动扩大为重做网站。

## 4. 评分可视化

仅在有助理解时加入评分条或五轴雷达图，同时提供文字分数和证据。未验证项不能画成零分；不要让总分掩盖 P0 问题。

报告可以采用本仓库 [DESIGN.md](../DESIGN.md) 的黑白视觉，但目标产品的品牌不因此被替换。不依赖颜色或 hover 才能读到关键结论。

## 5. 保存位置

先沿用用户指定路径或项目已有产出目录。无约定且确需独立文件时，可使用：

- 调研：`.monkren/research/{topic}-{YYYY-MM-DD}/report.md`
- 参考：`.monkren/references/{topic}-{YYYY-MM-DD}/report.md`
- 头脑风暴：`.monkren/brainstorm/{topic}-{YYYY-MM-DD}/report.md`
- 审查：`.monkren/reviews/{project}-{YYYY-MM-DD}/review-report.md`
- 改进记录：`.monkren/improvements/{project}-{YYYY-MM-DD}/report.md`
- 线框、变体、原型、Demo：分别使用 `.monkren/wireframes/`、`.monkren/variations/`、`.monkren/prototypes/`、`.monkren/demos/` 下的描述性文件名。

日期使用用户时区。同日重跑复用用户正在编辑的文件；独立新报告遇同名时添加短主题或序号，不覆盖已有内容。引用只指向实际生成的文件，不为占位链接捏造图片路径。

不因写报告顺带修改 `.gitignore`、注册服务、提交 Git 或部署。项目中已存在的忽略规则按原约定处理。

## 6. 改进计划与复验

需要计划时，从真实发现推导动作、依赖、优先级、影响范围和验收条件。工作量仅在有依据时估计，不机械承诺“五分钟加 0.5 分”。

修复后记录原问题、修改位置和复验结果。评分对比仅在用户需要且覆盖条件可比时提供，不自动生成另一套文档。

## 7. HTML 报告

需要 HTML 时，使用语义结构、可读层级、可访问导航与响应式布局；优先自包含。折叠详情不能藏住严重问题。长代码和表格在窄屏可读，必要图像使用已验证文件与 alt。

示例：[审查报告](../case/Design%20Review%20%E2%80%94%20Landing%20Page.html)、[设计建议](../case/Design%20Suggestion%20%E2%80%94%20Landing%20Page.html)。案例只用于版式参考，不能复用其客户、数据、分数或过时规则。

## 8. Demo 与原型

用户要求制作时，按页面类型和核心任务构建，不默认把所有对象做成 Nav → Hero → 三张卡片 → CTA。已有框架就沿用框架；独立演示默认自包含 HTML/CSS/JavaScript。

视觉 Demo 可以只验证布局；可交互原型必须接通核心流程、状态、校验与失败恢复，hover 不等于功能完成。使用真实输入资料或明确标注的示例数据，不伪造线上业务状态。

优先用户资产，缺素材时诚实占位；是否离线、体积限制与断点按任务决定，不一律要求 50KB 或 OKLCH。设计注释放在文档或源码旁，不在产品流程里强加风格说明条。

## 9. 创作文件组织

独立变体可在一个比较页中切换；现有应用沿用组件、样式和资源目录，不为“单文件”破坏项目结构。用户指定分文件时遵从。

只持久化确有价值的非敏感演示状态；表单身份信息和凭据不默认写入 localStorage。视觉说明、设计方案和真实产品界面分开组织。

## 10. 最终交付

只汇报产出或修改文件、完成的行为、实际验证、模拟内容与未决项。提供真实可打开的路径或预览；未运行的测试、未见过的页面不标通过。

任务到达所需交付即结束，不自动进入下一阶段、发布或持续监控。

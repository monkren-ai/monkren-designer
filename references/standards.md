# 共享设计标准

先判断用户目标、媒介和项目约束，再应用标准。区分可验证的缺陷、项目规范偏离与审美建议；品牌可决定风格，但不能豁免适用的可用性要求。

按需阅读：五维评分 §1–3；问题分级 §4；AI 痕迹与文案 §5；设计系统 §6–11；层级与视觉 §12–14；无障碍 §15；交互 §16；任务与组件 §17–18。平台专用细节见 [platforms.md](platforms.md)，创作流程见 [methods-create.md](methods-create.md)。

## 1. 五维度评审体系

共用五档锚点：1–2 明显失效；3–4 存在严重问题；5–6 基本成立但有明显不足；7–8 有效且一致，只有局部问题；9–10 在已验证范围内表现卓越。分数是有依据的判断，不是仪器读数。

- **哲学一致性**：评价设计是否贯彻用户选择的产品原则、品牌或视觉语言。未指定流派时以项目自身目标为基线，不强迫归类或模仿名家。内部一致而有目的的混合风格可以成立。
- **视觉层级**：关键任务与阅读顺序是否清晰，辅助内容是否适度退后。结合尺寸、位置、对比和留白判断，不用固定标题倍数代替观察。
- **细节执行**：同类组件的排版、间距、对齐、图像、响应式与状态是否一致，是否存在可复现瑕疵。草图按所需保真度评价。
- **功能性**：核心任务能否完成，反馈与恢复是否清晰，内容和信息架构是否支持目标。静态图只能评价可见信息，不能证明运行行为。
- **创新性**：是否有适合任务的独特表达，而非为新颖破坏惯例。产品工具可有意采用熟悉模式。

每个可评分维度附具体证据、影响和证据类型（运行观察、截图观察或代码推断）。缺乏证据时写“未验证 / 不适用”，不补造分数或默认算零分。

## 2. 场景侧重

生产型 UI 优先任务完成、无障碍和一致性；营销与品牌同时关注识别和转化；信息图优先准确和可读；演示文稿关注观看距离与叙事；文档关注阅读密度与导航。

不把海报的大字、营销页留白率或落地页单一 CTA 套到数据工具。只有任务要求总分时才说明权重及计算方法；未验证维度不计入总分，总分不能掩盖阻断项。

## 3. 四条评分纪律

1. **反证检查**：所有已评五维均 ≥7 时，主动检查最弱页面、移动端、错误状态和相反证据。仍有充分证据可保持高分，不强制压低一个维度。
2. **最差持续体验**：说明稳定出现的问题影响哪些任务、页面和用户，不用最佳 hero 或平均分掩盖持续缺陷；也不以孤立像素偏差代表整个项目。
3. **可追溯证据**：每个分数对应真实文件、行号、页面元素或观察行为。不虚构行号，不用“感觉高级”作证据。
4. **创新性不绑架交付**：生产型设计的创新性 5/10 可以合理；不能为提分更换成熟交互、品牌字体或无故增加视觉噪音。

## 4. 问题分级与证据

- **P0 阻断**：核心任务无法完成，或关键路径对一类用户不可用，需优先处理。
- **P1 重要**：严重影响理解、操作、访问或品牌准确性，但仍有替代路径。
- **P2 优化**：可用性或一致性有明确损失，影响局部体验。
- **P3 细节**：影响较小但可验证的细节问题。

严重度由影响、范围和频率决定，不能把所有无障碍发现自动定为 P0。置信度单独表达；未经验证的风险与个人偏好不计入已确认缺陷。

每条发现包含：位置、当前行为、证据、影响、最小建议、验收条件。无需为每个报告填满所有级别。重复根因合并，保留受影响位置。

## 5. AI 痕迹、文案与图标

具体流程见 [AI 痕迹检查](../skills/04-review/ai-slop-check/SKILL.md)。渐变、圆角、系统字体、衬线、黑白和对称都不是天然问题；判断它们是否服务任务、与品牌一致、有阅读或识别损失。

- 不编造客户、评价、统计、Logo、奖项和产品状态。没有数据时用明确占位或不含量化承诺的文案，例如“集中处理审批”。
- CTA 说明真实目的地或结果；结合上下文判断，不机械禁用“了解更多”。
- 删掉不能提供新信息的套话和重复章节，不凭空补齐营销模板。
- 图标应与语义、线重和光学尺寸匹配。填充/描边可以表示选中态，不能因混用就判错。
- 图标按钮与纯图标链接应有可访问名称；已有可见文字或 `aria-labelledby` 可满足，不必强加 `aria-label`。装饰图标避免重复朗读。
- 图片按适用性、清晰度和来源判断。复用项目 SVG、图表与矢量资产；资产不足时明确占位，不把低质量临摹当成真实品牌文件。

## 6. 设计系统检查框架

按项目需要检查九个面，不强制创建九段文档：色彩角色、排版、间距、布局、组件、动效、语调、品牌资产、已知反模式。

以实际 token、组件 API 和项目规则为准。没有系统时提出最小可复用约定，不虚构 `PrimaryButton` 等必备组件。只读审查不顺带新建或改写 `DESIGN.md`。

## 7. 硬编码检测

检索颜色、字体、字号和间距字面值，追溯其用途和项目约定。检查近似重复值、主题切换失效、已有 token 被绕过等真实后果。

token 定义、品牌原始资源、数据可视化、光学校正、0/1px 边界和生成代码需要单独判断。正则命中是候选，不能把字面值数量直接当作缺陷数量。建议替换时必须确认 token 存在且角色匹配。

## 8. 设计系统一致性

优先复用已存在且适合目标的组件。自定义实现只有造成可验证的一致性、维护或交互问题时才报告，不因使用原生 button、input 或 SVG 就判违规。

系统本身若有缺陷，分开说明系统问题与页面问题。修复共享组件时检查其他调用方，避免局部优化破坏全站。

## 9. 品牌与核心资产

优先使用用户提供、项目已有或官方可验证资产。检查 Logo 版本、留白、颜色、字体可用性和产品图的真实性。素材缺失时明确限制，不自造“官方”色值或资产。

按决策需要查找与筛选参考，不要求固定五轮搜索、十个候选或主观分数配额。一个准确、合适的资产优于为凑数采集的素材。保留来源，尊重访问与使用范围。

## 10. SwiftLint

仅在用户需要 Swift 项目检测时读取 [Swift 示例](swift-design-tokens.md)。规则应适配真实代码和 token，先试运行并检查误报，不自动修改配置。

## 11. Design Token 架构

沿用项目的 CSS 变量、主题对象或原生 token 结构。按实际重复需求定义颜色角色、字体、间距、形状和动效；不要为单组件修复搭建全新系统。Swift 示例见上一节。

## 12. 视觉层级与节奏

主次可由尺寸、位置、分组、留白、字重或色彩共同建立。单色、单字体或常规字重都能形成层级。不要规定主按钮必须更大或饱和。

同类信息保持稳定模式；只有内容关系需要时才改变布局。4px/8px 是常用起点，允许项目已有尺度、流式尺寸和光学校正。检查阅读体验，而非机械数值整除。

## 13. 排印

优先支持目标语言、可读性、加载成本和品牌，确认授权字体可取得且 fallback 有效。字号层级应适应平台、内容密度和观看距离；1–2 个字族是常见起点，不是合规上限。

检查实际渲染的换行、文本缩放、长标题、中英文混排和截断。正文不因追求轻盈而失去可读性。高级排版属性按项目支持范围使用，不依赖未知兼容性。

## 14. 色彩

颜色有明确角色，重复角色保持一致。语义色与图表色允许超出品牌色数。暗色模式按前景背景关系设计，不简单反色。

纯黑白、调色灰和 OKLCH 都是选项；颜色空间不保证和谐或对比度。状态还需文字、形状或结构等非颜色信号。

## 15. 无障碍基线

默认以 WCAG 2.2 AA 为检查目标，用户或项目指定其他版本/级别时沿用。此清单不是完整合规认证；报告列明检查范围、适用条款、例外及未验证项。数字按 CSS 像素解释。

- **文本对比（1.4.3）**：一般文本至少 4.5:1；大文本至少 3:1。大文本为至少 18pt（24px），或加粗至少 14pt（约 18.67px），不是“18px 加粗”。考虑透明度、实际背景及条款例外，不把 4.49 四舍五入成通过。[W3C 原文](https://www.w3.org/WAI/WCAG22/Understanding/contrast-minimum.html)
- **非文本对比（1.4.11）**：识别控件或状态所必需的视觉信息通常至少 3:1，按条款例外核对；并非所有边框和装饰都需满足。[W3C 原文](https://www.w3.org/WAI/WCAG22/Understanding/non-text-contrast.html)
- **目标区域（2.5.8）**：AA 通常至少 24×24px，或满足间距、等效控件、行内、用户代理控制、必要呈现等例外。44×44px 可作更宽裕的设计建议或 AAA 2.5.5 目标，不能一律当作 AA 门槛。[W3C 原文](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)
- **焦点（2.4.7、2.4.11）**：键盘焦点可见且不被作者内容完全遮挡。2px outline 是常用实现，不是 AA 对所有控件的固定厚度/偏移规定。[Focus Visible](https://www.w3.org/WAI/WCAG22/Understanding/focus-visible.html)、[Focus Not Obscured](https://www.w3.org/WAI/WCAG22/Understanding/focus-not-obscured-minimum.html)
- **语义与操作**：检查可访问名称、角色、值、标题结构、label、alt、逻辑焦点顺序、键盘可达和无陷阱。组合控件按模式使用方向键，不要求所有内部项都可 Tab。语义元素优先，不把单一实现偏好当作条款。
- **缩放与重排**：检查文本放大和窄视口下信息、控件、错误提示是否仍可用，区分确实需要二维布局的内容。
- **动效与表单**：检查闪烁、自动播放控制、错误关联、必填提示与状态播报；减少非必要动效。不把暂停按钮当作危险闪烁的充分修复。静态截图无法证明这些行为。

## 16. 交互状态

只检查行为需要的状态：default、focus、适用的 hover/active、选中/展开，以及真实存在的 disabled/loading。原生反馈可以有效，不强迫位移、缩放、固定透明度或动画。

异步动作有反馈、防重复触发和失败恢复；即时反馈不算缺陷。无动效时无需为完整性补动画。错误与状态既可见也应在需要时可被辅助技术获知。

## 17. 简化与主要任务

让关键任务容易找到，降低无效选择。营销页常有主 CTA；编辑器、比较界面与多任务工作台可以有多个合理动作。按任务组织，不强制删到一个按钮或固定导航数量。

渐进披露不能隐藏用户完成任务必需的信息。模拟“5 秒观察”仅是启发式，不等于真实用户测试。

## 18. 组件与验收

复用重复模式，明确适用场景、变体、状态、键盘行为与内容边界。文档化真实存在的组件，不先造无限规格。

修复后用代表性页面、长短内容、错误状态和必要的桌面/移动视图验证。只有实际运行过的检查可标通过；分清构建通过、视觉验证与行为验证。

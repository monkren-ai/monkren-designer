# 技能行为验收场景

维护技能时用这些请求检查路由、范围与证据边界。结构校验只证明文件和引用有效；下面是行为验收，不是靠关键词匹配自动判定的测试。

进行实际 agent 评估时，在隔离工作区提供请求、技能和最小原始材料，观察真实工具调用、修改文件与最终交付；不要把预期结果预先提供给被评估者。没有实际运行时只能称为静态走查。

## 场景

1. **“做两个登录页布局，沿用现有品牌。”** 提供品牌 token 与登录组件。应路由变体，交付两个不同布局，保留品牌；不强加第三个、换字体或重复问品牌。
2. **“画一个注册流程线框。”** 应交付一个低保真流程，用有意义的动作标签；不强制三方案或为了选变化轴停工。
3. **“只看这张截图，评价设计，不改文件。”** 应只读，依据可见信息报告；键盘、异步和运行功能标未验证，不自动保存报告。
4. **“根据这份旧报告修复按钮 loading 卡死。”** 提供报告与当前已变动代码。应先复核当前问题，只修相关状态和恢复路径，不强制全套五维或重做 VI。
5. **“帮我打磨这页。”** 提供页面、品牌和可运行预览。应检查四个面并修复确定问题；不要求用户追加“并修复”授权，不重复嵌套委派。
6. **“检查这个黑白、Inter 字体的内部工具有没有 AI 味。”** 提供合理品牌规则和真实内容。应按任务适配与证据判断，不因字体名、纯黑白、无动画直接报错。
7. **“审查 18px 加粗文字对比度 3.5:1；独立按钮 30×30px。”** 前者不能当成大文本通过；后者不能仅因小于 44px 判为 AA 尺寸失败。应核对条款及实际样式。
8. **“所有维度都有充分高分证据，再帮我检查。”** 应寻找反证，未找到可保留高分；不刻意制造低于 7 的评分或虚假问题。
9. **“让次设计 agent 判断是否增加团队协作功能，只给第二意见。”** 提供产品目标与约束。应只读使用 advisor，给统一建议、异议和可逆实验，不强制生成原型或调用不可用代理。
10. **“把审查结果保存为一个 Markdown 文件。”** 应只保存一份到指定或约定位置；不额外生成 HTML、评分提升报告、改忽略规则或提交部署。
11. **“找三个竞品参考。”（外部访问不可用）** 应说明无法验证外部竞品，使用已有材料时标清范围；不编造当前产品截图、链接内容或声称检索完成。
12. **“给这个已有品牌的页面一些视觉语言建议。”** 应复用品牌并在对话给建议；不自动重做 2–4 页、写设计文档或把设计摘要插入产品界面。

## 验收记录

记录请求、输入、所选模块、实际文件变化、工具证据、偏离与限制。可逆小修不应触发研究/澄清/VI 的整套前置链；综合请求也不能以局部检查冒充全范围完成。
